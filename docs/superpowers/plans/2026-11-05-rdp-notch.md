# RDP Notch and File Drop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A hover fly-out toolbar at the top of every RDP tab (Ctrl+Alt+Del, Win+R, full screen, display, audio, clipboard, files, reconnect, disconnect, info); dropping Finder files on the desktop pastes them into the window under the cursor (remote clipboard offer + click + Ctrl+V); dropping them on the notch's Files button puts them in a per-connection folder redirected into the session as drive `xpnd`.

**Architecture:** Pure Swift pieces first — options, the drop folder with safe names, key-sequence tables, a notch view-model over an `RDPNotchActions` protocol — each unit-tested; then the Objective-C session additions (key sequences, clipboard on/off, display requests, connection info, whole-desktop drop target); then the SwiftUI notch overlaid on RDP tabs in `TerminalWorkspace`; then editor/Settings fields and docs.

**Tech Stack:** Swift 6, SwiftUI/AppKit, Objective-C (`xpndRDP`), FreeRDP 3.33.0 (vendored; `rdpdr`/`drive` channels compiled in), Swift Testing.

**Spec:** `docs/superpowers/specs/2026-11-05-rdp-notch-design.md`

## Global Constraints

- Branch `feature/rdp-notch` off `feature/rdp-file-clipboard` (which holds `XPRDPClipboard` and the Mac→Windows file paste). Never commit `vendor/`.
- Drive redirection exposes exactly one folder: `~/Library/Application Support/xpnd/drop/<connection id>/` (`0700`), announced as device `drive` named `xpnd` via `freerdp_client_add_device_channel(settings, 3, {"drive", "xpnd", "<folder>"})` with `FreeRDP_DeviceRedirection = TRUE`, only when the connection's `dropDrive` is on. `copyIn` never writes outside the folder (a dropped symlink is resolved; a name resolving to `..` is refused).
- Safe names (drive only): ASCII letters, digits, space, `.`, `_`, `-`; everything else → `_`; a leading `.` → `_`; collisions get ` 2`, ` 3`, … before the extension. A desktop drop never types anything: it offers the dropped URLs on the remote clipboard through `XPRDPClipboard` (same path as a Finder copy), sends one left click at the drop point, then Ctrl+V — only while connected.
- Key sequences: Ctrl+Alt+Del = `Ctrl+Alt+End`; every scancode down has a matching up; typed text goes through unicode key events. The notch never keeps keyboard focus after a click (focus returns to the desktop) except while a popover is open. ⌘⇧N toggles the fly-out; the pin keeps it open.
- Session-only changes, except Display's "Set as this connection's default", which writes through `ConnectionEditing`. Display Control is negotiated for every connection (`SupportDisplayControl` TRUE always; `DynamicResolutionUpdate` only for fit). Clipboard on→off is live both directions; off→on with no channel loaded shows "Reconnect to enable" and reconnects with clipboard on for this session; Audio changes reconnect (tooltip says).
- Copy: tooltips "Send Ctrl+Alt+Del (sent as Ctrl+Alt+End)", "Open the Run box (Win+R)", "Full screen", "Display size", "Audio: Play here / Leave on remote / Off (changing reconnects)", "Clipboard sync on/off", "Files: drop here to put files in the xpnd drive; drop on the desktop to paste them where you are", "Open in Explorer", "Show drop folder in Finder", "Clear drop folder", "Reconnect", "Disconnect", "Connection info". Settings/editor copy: "File drop drive", "Clear drop folders: Never / On disconnect / After 7 days", button "Clear now".
- Never log file names, paths, keystrokes or session content. `make test` green; `swift build` warning-free; Conventional Commits; commit only compiling code; never `--no-verify`; never run `op`.

## Review Focus

1. A file named `x" & calc & "` dropped on the desktop is only ever offered as clipboard data — no typed command exists; dropped on the notch it lands in the drive under a safe name. (Task 2: safe-name tests; Task 5: the desktop-drop path calls `pasteFiles(_:at:)` and nothing else.)
2. Dropping a symlink to `/etc/passwd` or a file named `..` must not escape the drop folder. (Task 2 tests.)
3. A desktop drop while the session is disconnected or reconnecting must do nothing (no clipboard offer, no click, no Ctrl+V) and tell the user; a notch drop still lands in the drive. (Task 5 view-model test with the fake in the disconnected state.)
4. Clipboard off must stop *both* directions: no local poll, and server format lists ignored, so a Windows copy no longer lands on the Mac pasteboard. (Task 4: `XPRDPClipboard.enabled` test hook — with `enabled == NO`, `offerText:fileURIList:` is a no-op and the server-format-list handler returns without touching the pasteboard; unit-testable via the pure `formatsToAnnounce` path plus a flag check.)
5. Pin state and ⌘⇧N must not steal focus: after any notch action the desktop view is first responder again. (Task 6 manual checklist; the view-model test asserts `restoreFocus` is called after every action.)

  ```swift
  @MainActor protocol RDPNotchActions: AnyObject {
      var isConnected: Bool { get }
      var clipboardChannelLoaded: Bool { get }
      var connectionID: Connection.ID { get }
      var config: RDPSessionConfig { get }
      func send(_ steps: [RDPKeyStep])
      func pasteFiles(_ urls: [URL], at point: CGPoint) -> Bool   // offerFilesForPaste + click + ctrlV; false when not connected/no clipboard
      func setClipboardSync(_ on: Bool)
      func reconnect(with changes: (inout RDPSessionConfig) -> Void)   // e.g. audio change, clipboard on
      func requestDisplay(_ display: RDPOptions.Display) -> Bool
      func disconnect()
      func toggleFullScreen()
      func restoreFocus()
      var info: RDPConnectionInfo { get }                                 // Swift mirror of XPRDPConnectionInfo (defined in this task):
      // struct RDPConnectionInfo: Equatable { var desktopWidth, desktopHeight: Int; var codec: String; var latencyMs: Int?; var connectedSince: Date?; var certificateSubject, certificateFingerprint, gatewayHost: String? }
      func dropFolderCount() -> Int
      func copyIntoDropFolder(_ urls: [URL]) throws -> [String]
      func clearDropFolder() throws
      func revealDropFolder()
      func saveDisplayAsDefault(_ display: RDPOptions.Display)
  }
  @MainActor @Observable final class RDPNotchModel {
      init(actions: any RDPNotchActions)
      var isPinned: Bool; var isExpanded: Bool                             // hover/pin state owned by the view, mirrored here
      var audio: RDPOptions.Audio; var clipboardOn: Bool; var display: RDPOptions.Display   // session-only current values
      var dropCount: Int; var lastDropNames: [String]; var notice: String?  // "Copied 3 files into the xpnd drive" / failures
      func ctrlAltDel(); func winR(); func fullScreen(); func chooseDisplay(_:); func cycleAudio(); func toggleClipboard()

      var clipboardButtonTitle: String   // "Clipboard sync on" / "Clipboard sync off" / "Reconnect to enable clipboard"
  }
  ```
  Behaviour: every action ends with `actions.restoreFocus()`. `dropOnDesktop`: if `isConnected` and clipboard sync is on → `pasteFiles(urls, at: point)`; else `notice` says why and nothing is sent. `dropOnNotch`: `copyIntoDropFolder` → `dropCount`/`notice`. `toggleClipboard`: on→off `setClipboardSync(false)`; off→on: if `clipboardChannelLoaded` `setClipboardSync(true)` else `reconnect { $0.clipboard = true }`. `cycleAudio`: local → remote → off → local via `reconnect { $0.audio = next }`. `chooseDisplay`: `requestDisplay`; if false, `notice = "The server fixed the desktop size."`.
